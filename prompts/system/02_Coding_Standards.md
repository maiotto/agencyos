# AgencyOS - Coding Standards

Version: 1.0

Status: Frozen for MVP

---

# Purpose

This document defines the coding standards for the AgencyOS project.

Every source file generated by AI or humans must follow these standards.

---

# General Principles

- Write clean code.
- Keep methods short.
- Keep classes cohesive.
- Avoid duplicated code.
- Prefer readability over clever implementations.

---

# Folder Organization

AgencyOS.Api

- Controllers
- Middlewares
- Configuration

AgencyOS.Application

- DTOs
- Interfaces
- Services
- Validators

AgencyOS.Domain

- Entities
- ValueObjects

AgencyOS.Infrastructure

- Persistence
- Repositories
- Configurations

AgencyOS.Shared

- Constants
- Exceptions
- Utilities

---

# Controllers

Controllers must:

- Be thin.
- Receive DTOs.
- Call Application Services.
- Return ActionResult.
- Never access repositories directly.

---

# Services

Services must:

- Contain business orchestration.
- Be asynchronous.
- Use interfaces.
- Not know HTTP.

---

# Repositories

Repositories must:

- Be implemented in Infrastructure.
- Hide persistence details.
- Never contain business rules.

---

# DTOs

Use:

CreateMissionRequest

UpdateMissionRequest

MissionResponse

Never expose Domain Entities.

---

# Entity Rules

Entities must:

- Represent business concepts.
- Have meaningful names.
- Avoid unnecessary setters.

---

# Naming

Namespaces

AgencyOS.Api.Controllers

AgencyOS.Application.Services

AgencyOS.Domain.Entities

AgencyOS.Infrastructure.Repositories

Classes

PascalCase

Methods

PascalCase

Variables

camelCase

Constants

UPPER_CASE only when appropriate.

---

# Async

Use async/await.

Repository methods must be asynchronous.

Service methods must be asynchronous.

Controller methods must be asynchronous.

---

# Logging

Inject ILogger<T>.

Log:

- Errors
- Warnings
- Business events

Do not log sensitive information.

---

# Comments

Prefer self-explanatory code.

Use comments only when they add value.

---

# Formatting

Use default .NET formatting.

Indent with 4 spaces.

One class per file.

One public type per file.

---

# Dependency Injection

Always register services through extensions.

Avoid manual instantiation.

---

# Swagger

Every endpoint must include:

- Summary
- Response codes
- Request model

---

# Definition of Ready

Before implementing code:

- Read User Story.
- Read Acceptance Criteria.
- Read Engineering Principles.

---

# Definition of Done

Implementation is complete only if:

- Builds successfully.
- Follows architecture.
- Uses DTOs.
- Uses Dependency Injection.
- Uses Logging.
- Uses Validation.
- Appears correctly in Swagger.
